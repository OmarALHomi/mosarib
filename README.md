# بيننا — مستودع حساباتك ومعاملاتك

تطبيق أندرويد لدفتر الحسابات المشترك: مسرب، مزارع، دلال، مشتري/مجبري، وبقالة. يبدأ المشروع من دفتر محاسبي لموزعي مياه الآبار، وتُبنى عليه غرفة مشتركة بإقرار متبادل، وسوق للثمرة، وصلح بأقساط وسعاية، ومصروفات مزرعة.

> **حالة المشروع: قيد البناء وفق خطة معتمدة، وليس إصدار إنتاج بعد.** وجود شاشة أو مدير مزامنة لا يعني اكتمال الصلاحيات والمحاسبة والاسترجاع. الخطة الملزمة هي [خطة بناء «بيننا» المتكاملة v6](docs/BUILD_PLAN_V6_AR.md)، وتُقرأ معها [مراجعة الكود v4](docs/REVIEW_AND_SCALE_PLAN_V4_AR.md) التي تسرد المخاطر المؤكدة.

## المتطلبات والبناء

- Android Studio وJDK 17+ المتوافقان مع إعدادات Gradle/AGP في المستودع.
- Android SDK المطابق لـ `compileSdk` الحالي (36، minor API 1)، ومحاكي أو جهاز يبدأ من Android API 24.
- النسخة الحالية تستخدم Firebase Auth/Firestore وGoogle Drive لميزات الاتصال. `app/google-services.json` مرفق للبناء؛ لا يُعد بديلًا عن إعداد المصادقة والصلاحيات وOAuth في مشروع اختبار مستقل.

```bash
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest :app:lintDebug
```

**للتطوير:** استخدم مشروع Firebase تجريبيًا/Emulator ولا تختبر الكتابات على بيانات الناس. بعض ViewModels الحالية تبدأ listeners مبكرًا، وقواعد المستودع تحتاج إصلاحًا قبل نشرها لبيانات حقيقية. لم يُثبت نجاح البناء أو الاختبارات في بيئة المراجعة التي لا تتوفر فيها Java/Android SDK.

## المحلية والمزامنة

- دفاتر الري الأصلية والمصروفات تحفظ محليًا في Room.
- الميزات المشتركة الجديدة تستخدم Firestore؛ المشروع لم يعد «محليًا بالكامل بلا اتصال» كما كانت النسخة السابقة.
- توجد بداية لمزامنة حساب الري والعروض والصفقات، لكن استكمال Outbox وإعادة المحاولة والصلاحيات والتصالح المحاسبي من أولويات الإصلاح.
- النسخ الاحتياطي (بعد إصلاح PR-01) يشمل الجداول العشرة: العملاء والمستفيدون، جلسات الري، السندات، مصادر المياه، الإعدادات، روابط المسربين، عروض السوق، الصلوح، دفعات الصلوح، ومصروفات المزرعة — بما فيها الصفوف المؤرشفة والمصادر المعطّلة، وبما يحفظ نسبة السقية إلى العميل المتحمّل للدين وربط السند بجلسة.
- كل ملف جديد يعلن عن نفسه: `formatVersion` و`dbVersion` وقائمة `tables`، ولا يُسمّى «كاملًا» إلا إذا حمل الجداول العشرة. الملفات القديمة (خمسة جداول) تُقرأ مع تحذير صريح أنها ناقصة.
- الاسترجاع ثلاث مراحل: **معاينة** (عدد الصفوف وما سيُستبدل والأخطاء المانعة) ثم **نسخة أمان تلقائية** للوضع الحالي، ثم كتابة داخل معاملة واحدة تُلغى كاملة عند أي خطأ. لا يُحذف شيء لا يذكره الملف، ويُرفض الملف التالف أو الأحدث أو ذو المبالغ السالبة أو المعرّفات المكررة أو الروابط المفقودة قبل أي كتابة.
- لا تحذف بياناتك الأصلية بعد تصدير ملف، ولا تعتمد أي ملف قديم كنسخة كاملة.

## البناء والاختبار

- `.github/workflows/android-ci.yml` يشغّل عند كل دفع: `tools/ci_invariants.sh` ثم اختبارات الوحدة ثم lint (مانع) ثم بناء APK للتصحيح، ويرفع التقارير.
- `./tools/ci_invariants.sh` محليًا يفحص القرارات الثابتة: لا ترحيل مدمّر، تصدير مخطط Room، لا توقيع بمفتاح التصحيح في نسخة الجمهور، ثبات معرّف الحزمة واسم قاعدة البيانات، ولا مفاتيح متتبعة في Git.
- مخططات Room تُصدَّر إلى `app/schemas` مع كل بناء؛ لا تُحذف، فهي مرجع مقارنة الإصدارات.
- عند غياب مفتاح الإصدار تُبنى نسخة release **غير موقّعة** ولا تصلح للنشر؛ لا يوجد أي مسار احتياطي إلى مفتاح التصحيح بعد الآن.

## التوقيع والإصدار

إعداد البناء يقرأ توقيع الإصدار من `keystore.properties` غير المتتبع أو من متغيرات البيئة:

| المتغير | الوصف |
|---|---|
| `KEYSTORE_PATH` | مسار keystore؛ الافتراضي `my-upload-key.jks` |
| `STORE_PASSWORD` | كلمة مرور المخزن |
| `KEY_PASSWORD` | كلمة مرور المفتاح |
| `KEY_ALIAS` | اسم المفتاح؛ الافتراضي الحالي `mosarib_key` |

```bash
./gradlew :app:assembleRelease
```

**تحذير:** الإعداد الحالي قد يوقع release بمفتاح debug عند غياب إعداد الإصدار. هذا للاختبار فقط؛ يجب إزالة هذا المسار كشرط لتوزيع إصدار الجمهور. لا تضع مفاتيح أو كلمات مرور في Git، ولا تغيّر مفتاح التوقيع بين التحديثات.

## البنية الحالية

```text
app/src/main/java/com/baynana/
├── MainActivity.kt / MainScreen.kt    دخول، قفل، تنقّل يدوي
├── core/
│   ├── database/                     Room + ترحيلات 1–6 يدوية ثم 6→12 تلقائية
│   ├── license/                      ترخيص: تصريح موقّع (ECDSA) ومنع استرداد متكرر (ح١٣)
│   ├── security/                     قفل بصمة/قفل الهاتف وربط جهاز
│   ├── sync/                         المرايا السحابية القديمة (مُجمَّدة للعميل في ح١٥)
│   ├── ui/                           مكونات مشتركة
│   └── util/                         تنسيق، PDF، نسخ، Drive، مشاركة
├── features/
│   ├── customers / sessions / vouchers / pumps / reports (القديمة — تُنقّى في د٦)
│   ├── rooms / movements / statements / sync / handover
│   └── home / market / more / shell / dev / settings / about
└── ui/theme/                         Material 3 + Cairo + RTL

tools/key_generator.html              لوحة الأدمن: عقود، ترخيص موقّع، سجل تدقيق، رقابة سوق
tools/license_keygen.html             توليد زوج مفاتيح التصاريح (بلا إنترنت مطلقًا)
tools/ci_invariants.sh                حواجز القرارات الثابتة (تعمل محليًا وفي CI)
tools/admin_console_test.mjs          اختبار XSS للوحة الأدمن
tools/license_signer_test.mjs         اختبار موقّع التصاريح + المتجه الذهبي للتطبيق
tools/rules_guard.mjs                 حاجز بنية قواعد Firestore (بلا شبكة)
tools/firestore_rules_test.mjs        مصفوفة §8.2 على محاكي Firestore
tools/set_admin_claim.mjs             منح ادعاء الأدمن (مرة واحدة، بمفتاح خارج المستودع)
firestore.rules                       قواعد مفروضة: رفض افتراضي، ومصفوفة §8.2 تحرسها في CI
```

- Kotlin · Jetpack Compose · Room · Coroutines/Flow · Firebase.
- قاعدة البيانات: `water_distributor_db`، الإصدار **13**، ٣٠ جدولًا (الجداول العشرة القديمة + الدفتر المشترك والصلح والسوق والترخيص والتسليم اليدوي)، وكل ترقية لها مخطط مُصدَّر واختبار ترحيل حقيقي.
- الهوية المعتمدة (قرار المالك 2026-10-03): الاسم **«بيننا»**، والعنوان **«مستودع حساباتك ومعاملاتك»**، ومعرّف التطبيق `com.baynana.app`. لم يكن التطبيق مثبّتًا لأي مستخدم قبل هذا القرار، وهذا آخر وقت جاز فيه التغيير: بعده لا يُغيَّر المعرّف ولا مفتاح التوقيع أبدًا.
- اسم قاعدة البيانات يبقى `water_distributor_db`، ومساحة الأسماء في الكود صارت `com.baynana` (ح١ من الخطة، نُفِّذت بلا تغيير سلوكي).
- أول تشغيل يهيئ إعدادات ومضخة بداية، ولا يضيف ديونًا أو جلسات تجريبية لدفاتر المستخدم.
- **التسليم بلا إنترنت (ح١٩):** «المزيد ← التسليم بلا إنترنت» يجهّز حزمة نصّية مُبصَّمة من الحركات المعلّقة
  تُلصق في واتساب أو تُرسل ملفًّا، ويستوردها الطرف الآخر فيمرّ كل عنصر من نفس مسار المزامنة. لا حساب
  ولا خادم ولا شبكة، وإعادة استيراد نفس الحزمة لا تُضاعف شيئًا، والغرفة لا تُفتح إلا بقبول صريح.

## التحقق المحلي (بلا جهاز Android)

```bash
./tools/ci_invariants.sh          # الحواجز الثابتة: هوية، ترحيلات، مفردات، لوحة، قواعد
node tools/admin_console_test.mjs     # لوحة الأدمن: حمولات XSS تُعرض نصًّا (SEC-04)
node tools/license_signer_test.mjs    # موقّع التصاريح + طباعة متجه ذهبي لاختبار Kotlin
node tools/rules_guard.mjs            # بنية قواعد Firestore: لا قراءة عامة، وحالات §8.2
npm install --prefix tools            # مرة واحدة (أدوات Node)
tools/node_modules/.bin/firebase emulators:exec --only firestore --project demo-baynana \
  "node tools/firestore_rules_test.mjs"   # مصفوفة القواعد على المحاكي
```

اختبارات Kotlin وحدها تحتاج JDK/Android SDK، وتُشغَّل في CI (‏`./gradlew :app:testDebugUnitTest`).

## قبل الإطلاق

الصلاحيات وهوية الأطراف، صحة السداد والتقارير، النسخ والترحيلات، واختبارات القواعد والمزامنة هي بوابات إلزامية. بعد نجاحها يبدأ إطلاق صغير في عزلة واحدة؛ تفاصيل المهام والأولويات ومعايير الانتقال في [خطة v4](docs/REVIEW_AND_SCALE_PLAN_V4_AR.md).
