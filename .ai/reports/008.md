# Report 008: Stop duplicate imported operations, clean existing duplicates, fix expense totals

## Summary
Prevented duplicate operation and initial balance creation upon re-importing customer drafts by matching against existing imported sessions and vouchers. Added a pure scanner `ImportDuplicateFinder` along with a Settings maintenance tool ("فحص العمليات المستوردة المكررة") that previews duplicates (type mismatch twins and exact twins), creates a local backup first via `BackupManager.createBackupJson`, and deletes confirmed duplicates in a single Room transaction. Corrected operating expense calculations in `ReportsViewModel`, `ReportsScreen`, and `VouchersScreen` so customer disbursements are not counted as operating costs and do not reduce net profit.

## Backup Function Used
- `BackupManager.createBackupJson(getApplication(), db)` (followed by `loadBackups()` in `SettingsViewModel.deleteImportDuplicates`). This creates an encrypted internal `.back` JSON backup file in `context.filesDir/backups/` matching the local backup list format in `SettingsLocalBackupsTab`. If the backup fails for any reason (throws exception), deletion is aborted and no data is modified.

## Decisions and doubts
- Re-used existing DAO methods (`deleteSessionById` and `deleteVoucherById`) within a single Room `@Transaction` block (`db.withTransaction { ... }`) to avoid modifying DAO interfaces and schema while guaranteeing atomic deletion.
- In `ImportDuplicatesPreviewDialog`, customer names are resolved by joining candidate `customerId` against `customerDao().getAllCustomersIncludingArchived()` for transparent preview.
