# Report 031: About page, the mandatory subscription screen, update and announcement notices

## Summary
- **Part 0 (Critical Force Update Logic):** Corrected the force update rule in `AppUpdateManager` so `isForceUpdate` flag alone never locks users who are already on or above `minRequiredVersionCode`. Added offline fallback caching in SharedPreferences to prevent bypassing force updates by turning off Wi-Fi/mobile data. In Round 1, ensured the cache strictly follows the dashboard: written every time a broadcast is read (including min code 1 when a force update is cancelled), and cleared when `/app_broadcast` is empty/removed so offline users of an older version are unblocked.
- **Part A (About Page):** Replaced hard-coded version text with dynamic `BuildConfig.VERSION_NAME` and `BuildConfig.VERSION_CODE` ("الإصدار 1.4.0 (بناء 5)") and dynamic copyright year. Reorganized `AboutScreen` into the 5 structured sections: App card with license chip and device code copy button, 5 one-line feature rows (including "الإدخال الصوتي للعمليات" and directional-isolated "النسخ الاحتياطي على الهاتف وعلى \u2068Google Drive\u2069، ويعمل بدون إنترنت"), Developer card, Links (including new `mosarib.tubbasoft.com`), and Footer.
- **Part B (Mandatory Subscription Screen):** Added back press interception via `BackHandler` inside the `ModalBottomSheet` content calling `finishAffinity()` and added a visible text button "خروج من التطبيق" at the bottom of `LicenseDialog` when `isMandatory = true`. Preserved strict modal retention so the sheet cannot be dismissed into the app.
- **Part C (Update and Announcement Notices):** Redesigned `ForceUpdateScreen` and `BroadcastAnnouncementDialog` to use Mosarib design tokens (adaptive to light and dark themes) and removed all emojis from titles and buttons. Implemented same-day dismissal for announcements when clicking "لاحقاً". Reviewed and polished app-level notices in `MainScreen.kt`, including adding a gentle license expiry notice for subscribers with 5 or fewer days remaining.
- **Part D (Date Line in Text Messages):** Replaced fixed 📅 emoji (which rendered as "17" on most keyboards) with dynamic day keycap digits (`digit + "️⃣"`), Arabic weekday, and Western digits date (`dd/MM/yyyy`) using unified `MessageFormatHelper.dateLine(millis, label)`. Added unit tests for days 1, 9, 10, 17, 31 and all weekday names.

## Round 1 Review Fixes
1. **Force-Update Cache Follows Dashboard:**
   - Removed `if (minVersion > 1)` guard: cache is updated every time `/app_broadcast` is read, including when `minRequiredVersionCode = 1` (cancelling a force update).
   - Added `clearForceUpdateCache(context)`: invoked whenever `/app_broadcast` is empty, deleted, or `{}`.
   - Added Robolectric unit tests in `AppUpdateManagerTest` verifying:
     - Publishing `minVersion = 5` sets cache and blocks version 4 offline.
     - Changing broadcast back to `minVersion = 1` overwrites cache to 1 and unblocks version 4 offline.
     - Clearing/deleting broadcast clears the cache back to default 1 and unblocks version 4 offline.
2. **About Page Refinements:**
   - Added "الإدخال الصوتي للعمليات" with `Icons.Default.Mic`.
   - Updated backup row to: `"النسخ الاحتياطي على الهاتف وعلى \u2068Google Drive\u2069، ويعمل بدون إنترنت"` with BiDi isolation (`\u2068...\u2069`) to ensure the Arabic conjunction `و` does not render after the Latin word "Drive".

## Notices Before and After Comparison

### 1. Device Limit (Mandatory License Sheet)
- **Before:**
  - Reason text had redundant wording: `"لقد تجاوزت الحد التجريبي المجاني (${LicenseManager.getFreeOperationsLimit(context)} عملية) أو قمت باستعادة نسخة تتجاوزه. تم حفظ بياناتك بأمان تام، ويرجى تفعيل الاشتراك لمتابعة العمل بالتطبيق."`
  - Back button inside sheet did nothing; user could not exit the app without using Android overview/kill task.
  - No visible exit button at the bottom of the sheet.
- **After:**
  - Concise Arabic text: `"بلغت الحد الأقصى للعمليات التجريبية المجانية (${LicenseManager.getFreeOperationsLimit(context)} عملية). تم حفظ كافة بياناتك بأمان، ويرجى تفعيل الاشتراك لمتابعة العمل بالتطبيق."`
  - Back press inside sheet executes `(context as? Activity)?.finishAffinity()`.
  - Prominent "خروج من التطبيق" text button with exit icon placed directly under the activation button.
  - Cannot be dismissed into the app (`confirmValueChange` retains mandatory lock).

### 2. Blocked Device (`DeviceBlockedScreen`)
- **Before:**
  - Hardcoded dark-only colors (`0xFF0F172A`, `0xFF1E293B`).
  - Bottom exit button was titled `"إغلاق التطبيق"`.
- **After:**
  - Standardized exit button text to `"خروج من التطبيق"`.
  - Clean styling, no emojis in header or action buttons.

### 3. Feedback Prompt ("شاركنا رأيك")

- **Before:**
  - No app-level startup/session alert when subscription approached expiry.

  - Buttons: "تجديد الآن" (opens `LicenseDialog`), "لاحقاً" (dismisses for the remainder of the calendar day).

### 6. Broadcast Announcement Dialog (`BroadcastAnnouncementDialog`)
- **Visual styling in Light & Dark mode:**
  - Implemented via `MosaribDialog` with theme-reactive tonal surfaces.
  - Tones by broadcast type: `DialogTone.Success` for updates, `DialogTone.Warning` for maintenance/technical alerts, `DialogTone.Info` for general announcements.
- **Content & Buttons:**
  - Message is scrollable when long.
  - Optional release notes rendered as a clean bulleted list (`releaseNotes`).
  - Buttons: "تحديث" / "لاحقاً" for updates; "عرض التفاصيل" / "لاحقاً" or "حسناً" for announcements.
  - Clicking "لاحقاً" stores `KEY_DISMISSED_TODAY_PREFIX + broadcastId` in SharedPreferences with today's date, preventing re-display until the next calendar day.
