# Report 002: Import external ledger operations with the right type

## Summary
Added automatic file source detection (`MOSARIB_EXPORT` vs `EXTERNAL_LEDGER`) and intelligent date parsing supporting multiple formats, Arabic-Indic digits, and Excel serial numbers. Introduced a user-selectable debit recording mode ("صرف للعميل" / "سقي") in `CustomerImportReviewDialog` (defaulting to "صرف للعميل" for external ledgers and "سقي" for Mosarib exports), recording debit entries atomically within a Room transaction as `EXPENSE` vouchers or irrigation sessions. Fixed line breaking and vertical text truncation on customer cards, and updated recycle bin delete count failure behavior to return null and display a safe fallback message.

## Decisions and doubts
- For Excel serial numbers (such as `45231`), anchored calculations to `Calendar` at `1899-12-30` local time to ensure local day-of-year calculations remain timezone-consistent without day shifts.
- Retained the existing `mapRowsToDrafts(rawRows, existingCustomers)` signature for backwards compatibility while implementing `mapRowsToParseResult` returning `CustomerParseResult(drafts, source)`.
- Wrapped the entire customer and operation insertion loop inside `db.withTransaction { ... }` in `CustomersViewModel.confirmImport` to prevent partial import state if a record fails midway.
