# Report 001: Make permanent delete in the recycle bin safe

## Summary
Implemented safe atomic deletion for archived customers and the recycle bin using Room `@Transaction`. Permanently deleting an archived customer or emptying the recycle bin now safely deletes all associated records (`well_owner_purchases` with RESTRICT foreign keys, `vouchers`, and `water_sessions`) in the correct sequence before removing customer accounts, guarded by `AND isArchived = 1`. Confirmation dialogs now query and display the exact counts of records that will be deleted, and database exceptions are safely caught in `CustomersViewModel` and shown via error toasts without crashing.

## DAO Queries & Transactions
### 1. Count Queries
- Counts for single archived customer:
```sql
SELECT 
    (SELECT COUNT(*) FROM water_sessions WHERE customerId IN (SELECT id FROM customers WHERE id = :customerId AND isArchived = 1)) AS sessions,
    (SELECT COUNT(*) FROM vouchers WHERE customerId IN (SELECT id FROM customers WHERE id = :customerId AND isArchived = 1)) AS vouchers,
    (SELECT COUNT(*) FROM well_owner_purchases WHERE ownerCustomerId IN (SELECT id FROM customers WHERE id = :customerId AND isArchived = 1)) AS purchases
```

- Total counts across all archived customers in the recycle bin:
```sql
SELECT 
    (SELECT COUNT(*) FROM water_sessions WHERE customerId IN (SELECT id FROM customers WHERE isArchived = 1)) AS sessions,
    (SELECT COUNT(*) FROM vouchers WHERE customerId IN (SELECT id FROM customers WHERE isArchived = 1)) AS vouchers,
    (SELECT COUNT(*) FROM well_owner_purchases WHERE ownerCustomerId IN (SELECT id FROM customers WHERE isArchived = 1)) AS purchases
```

### 2. Deletion Queries & Sequences (under `@Transaction`)
- Single customer permanent deletion:
```sql
DELETE FROM well_owner_purchases WHERE ownerCustomerId IN (SELECT id FROM customers WHERE id = :customerId AND isArchived = 1)
DELETE FROM vouchers WHERE customerId IN (SELECT id FROM customers WHERE id = :customerId AND isArchived = 1)
DELETE FROM water_sessions WHERE customerId IN (SELECT id FROM customers WHERE id = :customerId AND isArchived = 1)
DELETE FROM customers WHERE id = :customerId AND isArchived = 1
```

- Empty recycle bin:
```sql
DELETE FROM well_owner_purchases WHERE ownerCustomerId IN (SELECT id FROM customers WHERE isArchived = 1)
DELETE FROM vouchers WHERE customerId IN (SELECT id FROM customers WHERE isArchived = 1)
DELETE FROM water_sessions WHERE customerId IN (SELECT id FROM customers WHERE isArchived = 1)
DELETE FROM customers WHERE isArchived = 1
```

## Decisions and doubts
- Kept all delete and count queries centralized within `CustomerDao.kt`. Because Room allows querying and deleting across database tables, this avoided spreading deletion logic across multiple DAOs or adding cross-DAO dependencies to `CustomerRepository`, keeping the diff minimal, cohesive, and robust.
- Added default parameters to `RecycleBinDialog` (`viewModel`, `onGetCustomerDeleteCounts`, `onGetTotalDeleteCounts`) so existing callers (such as `CustomersScreen.kt`, which was outside the allowed files) did not need to be touched.
- Deletion order explicitly executes `well_owner_purchases` first (solving the `RESTRICT` constraint), followed by `vouchers` (preventing orphan records that would otherwise be set to null), `water_sessions`, and finally `customers`.
